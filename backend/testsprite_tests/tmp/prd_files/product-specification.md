# Product Specification: RAWY Podcast Platform (Backend MVP)

**Product**: Rawy – منصة بودكاست  
**Scope**: Backend API (MVP)  
**Branch**: 001-podcast-platform-backend  
**Created**: 2026-03-04  

---

## 1. نظرة عامة

منصة بودكاست جاهزة للإنتاج مع ثلاثة أدوار: **User**، **Creator**، **Admin**. تشمل إدارة البودكاست والحلقات، التفاعل (إعجاب، تعليقات، متابعة)، نظام المتابعة، إشعارات الدفع، ورفع الملفات.

---

## 2. الأدوار والصلاحيات

| الدور | الوصف |
|--------|--------|
| **USER** | تسجيل، دخول، تصفح المحتوى، إعجاب، تعليق، متابعة منشئين |
| **CREATOR** | كل صلاحيات USER + إنشاء/تعديل/حذف بودكاست وحلقات، ملف تعريف منشئ |
| **ADMIN** | إدارة المستخدمين (قائمة، تعطيل، ترقية)، إزالة محتوى، أول أدمن يُنشأ من متغيرات البيئة (Admin Seed) |

---

## 3. الوظائف الأساسية

### 3.1 المصادقة
- تسجيل ودخول بـ email/كلمة مرور (JWT access + refresh، refresh مخزّن في DB).
- تسجيل دخول بـ Google و Facebook OAuth.
- تجديد التوكن دون إعادة تسجيل الدخول.

### 3.2 البودكاست والحلقات (Creator)
- إنشاء بودكاست: عنوان، وصف، صورة غلاف.
- رفع حلقات: عنوان، وصف، ملف صوتي (بدون وضع مسودة — تُنشر فوراً).
- تعديل وحذف البودكاست/الحلقات للمالك فقط.
- الملفات محلياً: `/uploads/audio`، `/uploads/images` (صوت حتى 200MB، صور حتى 10MB).

### 3.3 ملف المنشئ
- ترقية USER → CREATOR (ذاتية).
- ملف عام: bio، صورة، روابط اجتماعية، عدد المتابعين/البودكاستات.

### 3.4 التفاعل
- **متابعة/إلغاء متابعة** منشئ (علاقة واحدة لكل مستخدم–منشئ).
- **إعجاب/إلغاء إعجاب** حلقة (إعجاب واحد لكل مستخدم–حلقة).
- **تعليقات** مسطحة على الحلقات (بدون ردود متداخلة في الـ MVP).
- **عدد المشاهدات** للحلقة (مشاهدة واحدة محسوبة لكل مستخدم–حلقة).

### 3.5 الإشعارات
- تسجيل device token للدفع.
- عند نشر حلقة جديدة: إرسال إشعار دفع لجميع متابعي المنشئ (عبر Firebase).

### 3.6 التصفح العام
- قوائم البودكاست، تفاصيل الحلقة، ملف المنشئ: **متاحة بدون تسجيل دخول**.
- الإعجاب، التعليق، المتابعة: **تتطلب مصادقة**.

### 3.7 Admin Seed
- عند أول تشغيل: إنشاء أول أدمن من `ADMIN_EMAIL` و `ADMIN_PASSWORD` في `.env` إذا لم يوجد أي أدمن.
- أي أدمن إضافي يُنشأ فقط من خلال أدمن حالي عبر API.

## 4. الكيانات الرئيسية

| الكيان | الوصف المختصر |
|--------|----------------|
| **User** | اسم، email، هاش كلمة المرور، دور، device tokens، حالة نشط/معطّل، معرفات OAuth، refresh token |
| **CreatorProfile** | bio، صورة، روابط اجتماعية، عدد المتابعين، عدد البودكاستات |
| **Podcast** | عنوان، وصف، غلاف، منشئ واحد |
| **Episode** | عنوان، وصف، ملف صوتي، مدة، عدد المشاهدات، عدد الإعجابات |
| **Comment** | نص، مستخدم، حلقة، تاريخ |
| **Like** | مستخدم + حلقة (فريد) |
| **Follow** | متابع + منشئ (فريد) |
| **View** | مستخدم + حلقة (فريد) |

---

## 5. التقنيات والقيود (MVP)

- **Backend**: NestJS، REST API.
- **DB**: MongoDB فقط.
- **المصادقة**: JWT + Passport (Local, JWT, Google, Facebook).
- **الإشعارات**: Firebase Admin SDK.
- **التحقق**: class-validator على كل المدخلات.
- **التوثيق**: Swagger على `/api/docs`.

**خارج النطاق في الـ MVP**: مدفوعات، إعلانات، بث مباشر، بحث (Elasticsearch)، Redis، توصيات، ميكروسيرفس، تحقق البريد، استعادة كلمة المرور، تعليقات متداخلة، لوحات تحليلات، rate limiting.

---

## 6. معايير النجاح المختصرة

- تسجيل/دخول وتلقي توكنات في أقل من 5 ثوانٍ.
- منشئ ينشئ بودكاست ويرفع حلقة (مثلاً 50MB) في أقل من 30 ثانية.
- إشعارات الدفع تصل للمتابعين خلال 60 ثانية من نشر الحلقة.
- منع تكرار الإعجاب/المتابعة/المشاهدة 100%.
- واجهة توثيق كاملة لجميع الـ endpoints.
- تجديد التوكن يعمل دون إعادة تسجيل الدخول طالما refresh token صالح.
